<Info>
  Generated variants return the same image for the same seed and options. Portraits are stable for the same seed and gender within the current catalog. Catalog updates are infrequent, but can remap a seed.
</Info>

## Usage

<View title="React" icon="https://pictum.dev/v1/icons/devicon:react.svg">
  <CodeGroup>
    ```tsx Component
    import { Avatar } from "@pictum/react";

    <Avatar
      seed="customer-123"
      variant="portrait"
      gender="female"
      size={256}
      alt="Customer"
      className="size-10"
    />
    ```

    ```tsx Hook
    import { useAvatar } from "@pictum/react";

    export function CustomerAvatar() {
      const asset = useAvatar("customer-123", {
        variant: "portrait",
        gender: "female",
        size: 256,
      });

      return <img src={asset.url} alt="Customer" className="size-10" />;
    }
    ```
  </CodeGroup>

  #### Props

  <ResponseField name="seed" type="string" required>
    The `seed` prop is hashed to select the generated design or catalog portrait; reuse it to keep an avatar stable. Example: `customer-123`.

    <Warning>
      Seeds may be logged or cached. Never use sensitive data.
    </Warning>
  </ResponseField>

  <ResponseField name="variant" type='"identicon" | "gradient" | "monogram" | "portrait"' default="monogram">
    The `variant` prop chooses the visual strategy used to produce the avatar: identicon, gradient, monogram, or portrait. Example: `portrait` selects a catalog photo.
  </ResponseField>

  <ResponseField name="gender" type='"any" | "male" | "female"' default="any">
    For portraits, the `gender` prop limits catalog selection; `any` uses the full catalog, and the prop does not apply to generated variants. Example: `female` limits selection to female portraits.
  </ResponseField>

  <ResponseField name="format" type='"jpg" | "png" | "webp" | "svg"' default="svg; portrait: webp">
    The `format` prop controls how the avatar `src` is encoded; generated variants support SVG and raster output, while portraits are raster-only. Example: `webp` requests a WebP source.
  </ResponseField>

  <ResponseField name="size" type="integer" default="256">
    The `size` prop requests an exact square raster source. Display dimensions remain controlled by `width`, `height`, or CSS. Accepted range: `16`-`1024`. Example: `256`.
  </ResponseField>
</View>

<View title="URL" icon="https://pictum.dev/v1/icons/tabler:protocol.svg">
  ```text
  https://pictum.dev/v1/avatar.{format}?seed={seed}&variant={variant}&gender={gender}&size={size}
  ```

  #### Usage

  ```html
  <img
    src="https://pictum.dev/v1/avatar.webp?seed=customer-123&variant=portrait&gender=female&size=256"
    alt="Customer"
    width="40"
    height="40"
  />
  ```

  #### Parameters

  <ResponseField name="seed" type="string" required>
    The required `seed` query parameter is hashed to select the generated design or catalog portrait; reuse it to keep an avatar stable. It accepts `1`-`128` URL-safe ASCII characters, must start and end with a letter or number, and may otherwise contain letters, numbers, `.`, `_`, `~`, `@`, `+`, or `-`. Example: `customer-123`.

    <Warning>
      Seeds may be logged or cached. Never use sensitive data.
    </Warning>
  </ResponseField>

  <ResponseField name="variant" type='"identicon" | "gradient" | "monogram" | "portrait"' default="monogram">
    The `variant` query parameter selects the visual strategy. Example: `portrait` selects a catalog photo.
  </ResponseField>

  <ResponseField name="gender" type='"any" | "male" | "female"' default="any">
    The `gender` query parameter limits portrait selection. It is only valid when `variant=portrait`.
  </ResponseField>

  <ResponseField name="format" type='"jpg" | "png" | "webp" | "svg"' required>
    The path extension controls the response encoding. Portraits support JPG, PNG, and WebP; generated variants also support SVG. Example: `webp`.
  </ResponseField>

  <ResponseField name="size" type="integer" default="256">
    The `size` query parameter requests an exact square raster source from `16` to `1024` pixels. It is only valid for JPG, PNG, and WebP. Display dimensions remain controlled by `width`, `height`, or CSS.
  </ResponseField>
